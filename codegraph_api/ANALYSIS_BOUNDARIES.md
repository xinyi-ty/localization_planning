# 基础查询能力边界

本服务提供仓库初始化、索引同步及基础代码查询，不提供测试分析或完整源码单元组装接口。

## 查询与源码同步

查询读取 CodeGraph 索引或由其生成的依赖图缓存，不自动初始化或同步仓库。源码修改后应先调用 `sync`，再重新获取符号 key。索引范围由项目根目录、语言策略及 SDK 忽略规则决定。

## 函数与调用

- `getAllFunctions` 返回索引中的 function 和 method，不判断测试身份。
- `getCallees` 从预构建依赖图返回直接 calls 边及已解析的函数／方法目标，不递归追踪调用，也不分析对象来源、接收者或参数传递。
- 原生调用边可能保留无法找到目标节点的引用；这不等同于完整的未解析引用查询。

## 位置与源码

- `getLocation` 返回函数／方法所在文件及 SDK 记录的最近所属 class、struct 或 interface。
- `getContent` 按符号 key 返回 SDK 提供的源码，按文件选择器返回整文件原文。
- 符号源码不保证包含必要导入、全局变量、外层作用域或跨文件实现；整文件可能包含无关声明。
- getContent 的 C++ 类型查询会全局收集已索引的类外方法实现；C# partial 查询会合并限定名、泛型数量、外层类型及已知项目范围匹配的部分。没有 csproj 时，C# 以整个索引仓库为范围；不执行 MSBuild，不能保证复杂编译配置中的归属。
- 合并结果是以空行连接的源码片段，不补齐命名空间、导入及其他依赖；SDK 没有生成节点的实现（如部分静态字段定义）仍不能覆盖。源码合并不改变 getLocation 或依赖图的类归属规则。

## 依赖

- initialize / sync 完成后全量构建函数、类、文件依赖图并原子替换缓存；getCallees / getDependencies 从图查询，不在每次查询时聚合 SDK 关系。图缓存缺失、损坏或版本不兼容时从已有索引重建。
- `getDependencies` 只返回直接依赖，不递归求闭包。
- class 层聚合 calls、extends、implements、instantiates，并按最近所属类型归并目标。
- file 层另外包含 imports，按目标文件归并。
- 类归属只沿 SDK contains，不推断 C++ 类外实现归属，也不合并 C# partial，因而原有缺失/分离的类型关系仍会影响类依赖结果。
- 全局变量引用、类型引用及其他语义关系不保证被这些查询完整覆盖；空列表不能证明没有依赖。
- 外部库名称、导入原文、别名和位置没有独立的结构化输出，需调用方补充分析。

## 测试分析与组装

测试发现、fixture 和生命周期、参数化、对象传递、模块初始化以及安全分批由调用方结合语言与测试框架规则处理。基础图查询不保证裁剪后的测试可以独立运行。
